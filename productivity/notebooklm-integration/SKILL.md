# notebooklm-integration

Firstline `notebooklm` (package `notebooklm-py`, binary `notebooklm`) — PRIMARY. Legacy `nlm` CLI is FALLBACK (headless auth broken; only use with live desktop Chrome on `--remote-debugging-port=9222 --remote-allow-origins=`). Auth/config in native workspace (`.hermes/workspace/notebooklm/`), profile at `.notebooklm/profiles/default/storage_state.json`. Verify before claiming functional.

Procedure:
1. Check binaries: `which nlm` (v0.1.12, `notebooklm-cli`), `which notebooklm` (v0.8.2, `notebooklm-py`), `python3 -c "import notebooklm"`.
2. Install fallback: `pip install --break-system-packages notebooklm-py` (or `uv --system` in venv).
3. Check auth: `notebooklm auth status --profile default` (or `nlm auth status --profile default`).
4. If profile missing: migrate `.nlm/env` cookies/auth (`NLM_COOKIES`, `NLM_AUTH_TOKEN`) into `.notebooklm/profiles/default/storage_state.json`; set workspace to `.hermes/workspace/notebooklm/`.
5. Confirm workspace native (`.hermes/workspace/notebooklm/`) — no `.openclaw/` references.
6. Verify with safe real call (e.g., `notebooklm list` or profile check), never synthesize results.
Pitfalls: headless `nlm login` / `notebooklm login` blocked by CDP WebSocket 403 (existing Chrome on port 9222 launched WITHOUT `--remote-allow-origins=*`). Fix: kill blocking Chrome (check `ss -tlnp | grep 9222`; kill PID using `.hermes/browser-profile` or stale profile without flag), then retry — `nlm/utils/cdp.py` line 130 already includes `--remote-allow-origins=*` for newly launched instances. Profile sync gap: after interactive `notebooklm login` completes (new `.nlm/chrome-profile/` created), nlm profile files (`.local/share/nlm/profiles/default/cookies.json`, `.notebooklm/profiles/default/storage_state.json`, `.nlm/default.json`) are NOT auto-updated — `nlm auth status --profile default` still reports expired cookies even with a fresh Chrome session. Manually sync by copying cookies (`.nlm/chrome-profile/Default/Cookies` → `.local/share/nlm/profiles/default/cookies.json`) AND create `.nlm/profiles/default/` with the cookie file so `nlm` finds the profile; cookie-only sync without `.nlm/profiles/default/` still yields "Profile not found". If the user selects "use Chrome without a profile" inside `nlm login`, no `Default/Cookies` file is produced — `nlm auth status` will fail; retry login selecting an actual Chrome profile so a cookie file exists to sync. When cookies are under a named Chrome profile (e.g. "Profile 1" / "Work"), sync from that path: `cp "/home/tim/.config/google-chrome/Profile 1/Cookies" .local/share/nlm/profiles/default/cookies.json`. Copying from an alternate source requires quoting paths with spaces. `no nlm status`; `.env` protected (credential store — never `cat`); headless login blocked by 403 when stale Chrome blocks port; previous session evidence lives in `clawbak/` archive, not active session — verify with `skill_view` before assuming configured; vault item `notebooklm-python-cli` (`tim@inc2biz.com`) can link profile without exposing secret; `notebooklm-py` requires `pip install --break-system-packages notebooklm-py`; don't harden negatives — capture the fix (install/auth/config step), not 'tool broken'; when `nlm` fails use Composio (`composio` skill / `composio-cli`) as firstline fallback (user preference — saved from session); never invent notebook names — retrieve from real session (`clawbak/` archive or vault-linked profile), never synthesize. Subdomain rename: Google renamed `notebooklm.google.com` to `notebook.google.com`; `nlm` auth breaks against the old subdomain until `nlm` CLI or `notebooklm-py` updates to target the new domain. Until the update lands, expect auth failures regardless of valid cookies/profile.
